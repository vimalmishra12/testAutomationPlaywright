## Continuity model (evidence)
`core/runner/testrunner.js:58-73` — each Mocha `describe` = one execution suite; every suite after
the first gets a fresh browser context (`createFreshContext`), runs its `Before` once → its `Test`
cases in order (`BeforeEach`/`AfterEach` empty in this exec file) → its `After` once. Therefore the
`Test` cases inside a suite share one continuous session (each continues from the prior case's page
state), each suite starts fresh with its own login, and the suites are independent of one another.
`Before`/`After` (login/logout) are not `Test` cases and are documented once as shared setup/teardown.

## Priority scale applied (test weightage)
- **High (25)** — the case proves a suite's primary capability or writes data: launching a component

  Teacher's Resources, the note lifecycle (open pane, add, save, verify, delete), and the assignment path
  (wizard entry, name, students, Assign).
- **Medium (48)** — supporting navigation and reader/view controls: Class Materials, bundle listing,
  reader-loaded checks, dropdown content, Back / Home, layout, fit, zoom, Tools, summary view.
- **Low (4)** — exit checks and coverage that repeats a path already proven in another suite
  (S2-TC8, S2-TC9, S6-TC12, S6-TC18).
