# Walkthrough — claude-skill-discovery

## Session 1 — 2026-09-29

## Summary
Made Claude Code discover the three repo skills on its own, without moving them: the skills stay in
`.agent/skills/` (the team's other AI tools read them there) and a new script generates pointers in
`.claude/skills/`, the only folder Claude Code scans. Also added a "pick the skill yourself" routing
table to CLAUDE.md and tightened the skill descriptions, because the team — many newly onboarded —
never names a skill: they pull from git, hand over test cases and say "automate this".

## Changes Made

### 1. testAutomation_v1.0/tooling/syncClaudeSkills.js
- **Type:** Created
- **Layer:** Tooling (design-time, AGENTS.md §9 — nothing in the framework requires it)
- **What changed:** for every `.agent/skills/<name>/SKILL.md`, writes
  `.claude/skills/<name>/SKILL.md`: the source frontmatter copied verbatim (`name` + `description`,
  which Claude uses to choose a skill) plus a body telling Claude to read and follow the source file.
  `--check` reports missing / out-of-date / stale pointers and exits 1 without writing. Removes a
  pointer whose source skill is gone, but only if it carries the GENERATED marker (a hand-made
  Claude skill is never touched). Refuses a skill whose `name` differs from its folder or is not
  lower-case-hyphenated (≤ 64), or whose `description` exceeds 1024 characters (Agent Skills limit).
  Paths resolve from the script's own location, so it runs from the repo root or from
  `testAutomation_v1.0/`. Invalid skills print a one-line `ERROR:` and exit 1.
- **Why:** Claude Code only auto-discovers `.claude/skills/`; the skills had to stay in
  `.agent/skills/` for the team's other tools; symlinks are unreliable with git on Windows (the
  team's platform); full copies would drift. Generated pointers keep one source and make drift
  detectable.
- **Verified:** `--check` on the empty state → 3 missing, exit 1; generate → 3 created; `--check`
  from both working directories → OK, exit 0; a 1100-char description → refused, exit 1; a name/folder
  mismatch → refused; a tampered pointer → "out of date", exit 1; a stale marked pointer → reported,
  then removed; an unmarked hand-made skill → left alone. All throwaway fixtures removed.
